Codex向け開発指示書
異界どうぶつ調査局（仮）
0. 作業方針
この指示書を基準に、スマートフォン優先・PC対応のブラウザゲームを設計・実装すること。
このプロジェクトでは、金銭的コストが発生しない範囲の通常開発作業は都度確認せず進めてよい。
以下を重視する。
スマートフォンで遊びやすい
日本の子供でもルールを理解できる
PCでも問題なく遊べる
1人でもゲームとして成立する
友人対戦ができる
生音声を永続保存しない
音声処理は可能な限りクライアント側
Cloudflare無料枠を基本とする
有料AI APIをランタイムで使用しない
3Dを使わない
UIと演出には十分な開発時間を使う
Prisma Abyssの既存キャラクター素材を再利用する
画像生成機能が利用可能なら背景・動物・UI装飾の制作に積極的に使用する
Cloudflare等について、有料プランへの変更や課金が必要になる場合のみ作業を止めて確認すること。
1. ゲームの核
基本コピー：
この8匹の中に、動物に化けた異界人がいる！
プレイヤーは二つの役割で遊ぶ。
異界人
動物の鳴き声を真似して、本物の動物にまぎれる。
調査員
「音声分析装置」を使い、8匹の鳴き声を聞き比べて異界人を見つける。
重要なのは、
単なる「どれが偽物？」クイズではない。
異界人側のプレイヤー自身が、
録音 ↓ 加工 ↓ 偽の動物音声を作る ↓ 他人またはCPUを騙す
という生成行為を行う。
上手な人：
本当に本物と区別できず面白い。
普通の人：
推理ゲームとして成立する。
下手な人：
明らかに変な鳴き声になり、それ自体が面白い。
上手さの全レンジをゲームの面白さにすること。
2. 世界設定
人間界では最近、動物に化けて潜入する「異界人」が発見されている。
見た目だけでは本物の動物と区別できない。
そこで人間側は、
異界音声分析装置
を開発した。
この装置を通すことで、動物の声を分析できる。
ただし装置を通した音声は独特の機械的な音になる。
これをゲーム内設定として利用する。
3. 全音声を同じ装置へ通す
ゲーム上の最重要仕様。
本物の動物音声も、
プレイヤーの鳴き真似も、
CPU用の鳴き真似も、
必ず同じ分析→再合成処理を通す。
生の猫：
音声分析装置 ↓ ゲーム内の猫音声
人間の猫真似：
音声分析装置 ↓ ゲーム内の猫音声
という構造にする。
これにより、
「音質が機械っぽいから人間」
というメタ推理を不可能に近づける。
4. 動物音声を加工するメリットも利用する
本物の動物素材についても、単に原音を再生しない。
分析後の音声レシピに、
安全な範囲で、
音程
声の太さ
再生速度
揺れ
ノイズ感
微量のEQ差
微量の距離感
などを変化させる。
これによって、
同じ元録音から複数の「個体差」を作れるようにする。
ただし加工しすぎて、
「猫なのに猫に聞こえない」
状態にはしない。
動物ごとに加工可能範囲を設定すること。

6. 本物音源のデータ量
理想：
各動物6〜10種類以上の元音源。
ただしMVPでは、
3〜5種類程度の元音源から開始してよい。
そこから音声分析装置によって安全な変種を生成する。
ただし同じラウンド内で、
同一元音源から作った近似音を複数出すことは極力避ける。
公式音声データには、
"sourceFamilyId"
を持たせる。
同じsourceFamilyIdを同一ラウンドへ複数出さないことを基本とする。
7. 音源ライセンス
外部から本物の動物音声を取得する場合、
ライセンス確認を必須とする。
優先：
自作素材
CC0
商用利用可能なCC素材
その他利用条件を明確に満たせるもの
必ず、
source URL
author
license
attribution
をデータとして保持する。
ランダムにネットから音声を拾って使用しない。
8. 音声を「文字データ化」する
生音声そのものを対戦データとして扱わない。
ゲーム内部では、
VoiceRecipe
という再合成可能な数値データへ変換する。
VoiceRecipeはJSONまたは同等の構造化データ。
9. VoiceRecipe V1
概念：
type VoiceRecipeV1 = { version: 1
durationMs: number frameRate: number seed: number
frames: Array<{ pitch: number amplitude: number voicing: number noise: number spectralBands: number[] }> }
実際の形式は技術検証によって改善してよい。
重要なのは、
元のPCM/WAV/WebM等を保持しなくても、十分特徴的な音を再現できること。
10. 推奨分析方式
最初の技術検証では、
約20〜40ms程度のフレーム単位で、
基本周波数
音量
有声音率
ノイズ比
スペクトル包絡
16〜24程度の周波数帯
を取得する方式を試す。
目標：
1音声につき、
数KB〜20KB程度
のVoiceRecipe。
数MBの音声Blobを対戦中に運ぶ設計にはしない。
11. 再合成
Web Audio API / AudioWorkletを使用。
基本：
有声音源 + ノイズ音源 + スペクトルフィルター
による簡易ボコーダー方式を第一候補とする。
同じVoiceRecipeとseedから、
各クライアントでほぼ同じ音を再生成できるようにする。
ノイズ生成には必ずseed付き乱数を使用。
12. 音声技術検証を最初に行う
ゲーム本編を作る前に、
Voice Lab
を作成すること。
URL例：
"/dev/voice-lab"
機能：
1. マイク録音
2. VoiceRecipe変換
3. 生音声再生
4. VoiceRecipe再合成音再生
5. 波形比較
6. VoiceRecipe JSON表示
7. データサイズ表示
8. 加工スライダー
9. JSON Export
10. JSON Import
動物音声も読み込めるようにする。
13. 音声方式の合格条件
VoiceRecipeへ変換した、
本物の猫
と、
人間が真似した猫
を同じ再合成器で聞いたとき、
どちらも同じ「分析装置を通した音」に聞こえること。
これが成立するまで対戦サーバー実装を急がない。
14. VoiceRecipe方式が不十分だった場合
すぐに設計全体を捨てない。
Feature Flagを用意する。
AUDIO_TRANSPORT_MODE = "VOICE_RECIPE" | "TEMP_PROCESSED_AUDIO"
第一目標：
VOICE_RECIPE。
どうしても認識可能な品質が得られない場合のみ、
加工済み短時間音声を試合中だけ一時転送する方式を比較検証する。
ただし生録音の永続保存は禁止。
最終判断用にVoice Labで比較可能にする。
15. マイク録音
スマホ優先。

約0.4〜2.5秒。
最大3秒程度。
ユーザー操作：
「こえをとる」
タップ。
録音開始。
もう一度タップ：
停止。
最大時間到達：
自動停止。

極端な高周波除去
極端な低周波除去
出力ピーク制限
VoiceRecipe化
最終出力にはLimiterを入れる。
突然大音量が出ないようにする。

47. CPU判定アルゴリズム
各動物について、
公式の本物VoiceRecipe群から、
「その動物らしさ」の統計を作る。
例：
pitch中央値
pitch範囲
duration分布
spectralBands平均との差
noise分布
contour特徴
各スロットの音が、
その動物の本物分布からどれだけ外れているかを、
suspicionScore
として算出。
CPUキャラごとのweightを掛ける。
最後にskillに応じたノイズを加える。
CPUはsuspicionScoreの高いK匹を選択。

115. ゲームの最終思想
これは、
「動物の鳴き声クイズ」
ではない。
人間が動物の偽物を作り、それを他人が見破るゲーム。
本物の動物音源は問題素材。
音声分析装置は、
人間と動物を同じゲーム空間へ載せるための技術。
CPUはソロプレイヤーの相手。
Prisma AbyssのキャラクターはCPUへ人格を与える。
Cloudflareは友人対戦だけを低コストで成立させる。
Community Recipeは、
プレイヤー自身を将来のゲームコンテンツへ変える。
最終的に目指すのは、
遊ぶ人が偽物を作るほど、ゲームの問題が増え、上手い人も下手な人も面白さになる構造。
ただし、
他ユーザーの参加がない状態でも、
公式動物データ + 公式Human Recipe + CPU
だけでゲーム全体が成立することを絶対条件とする。
